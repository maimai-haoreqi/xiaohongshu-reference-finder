# mm 通用小红书找参考

稳定执行：对齐 Brief → 小批候选校准 → 扩搜 → 详情核验 → 按需归档。赛道知识和历史语料来自本轮对话或用户指定的外部 Profile；通用数据门槛使用本 Skill 的默认值，用户本轮要求或 Profile 可覆盖。

## 路由

选择最轻的模式：

- **单条核验**：用户给出链接，只核验是否符合本轮标准。
- **漏检复查**：核验漏检笔记，并沿标题、Tag、目标用户和场景补搜。
- **主题搜索**：围绕一个主题，先给 5–8 条高潜候选供用户校准，再扩搜。
- **系统建库**：覆盖用户指定的搜索矩阵、去重、详情核验和缺口报告。

写入表格或外部系统是独立的归档步骤，必须由用户明确要求。

## 1. Brief 闸门

先从当前对话和用户指定的 Profile 填写：赛道、主题/目的、目标用户及阶段、痛点场景/任务、内容任务/形式、时间与互动门槛、平台范围、交付范围。

默认按以下任一条件筛选小红书笔记：

- 发布于近半年且点赞量达到 1000 以上；
- 发布于近一周且点赞量达到 100 以上。

用户本轮指定了其他时间窗或互动门槛时，以本轮要求为准。

有任何会改变搜索空间的关键项不明确时，读取 [references/interview.md](references/interview.md)，在搜索前只问缺失问题。用户没有指定 Profile 时不要自行读取其他项目或赛道的历史资料。

## 2. 搜索与校准

需要搜索时读取 [references/search-protocol.md](references/search-protocol.md)，复用 Codex 内置浏览器中已登录的小红书会话。

主题搜索先执行发现层，只记录低成本字段，累计 5–8 条高潜候选后暂停。逐条编号，并明确询问：“哪一条最接近本次想讲的内容和目的？接近的是核心观点、内容结构、具体方法还是表达方式？”只有用户明确到候选编号或标题，并说明接近点后，才把它确定为母稿并据此扩搜。用户只回复“对”“这个”等指代不明的内容时继续确认，不得根据当前打开的网页、界面焦点或候选顺序推断母稿。已有足够且指向明确的正反例时可直接扩搜。

系统建库覆盖 Brief 指定范围，但仍按发现层 → 复核层 → 入库层推进。连续两个扩展分支没有新增合格候选即可停止。

## 3. 外部 Profile 与语料

需要建立赛道 Profile 时读取 [references/profile-format.md](references/profile-format.md)。Profile 是可覆盖更新的当前真源；历史案例和搜索日志放在其项目目录，不放进 Skill。

用户提供结构化参考库时，可从本 Skill 目录运行：

- `ruby scripts/dedupe-records.rb '<数据文件>' '<链接或标题>'`
- `ruby scripts/search-records.rb '<数据文件>' '<查询词>' [返回数量]`

只读取脚本返回的少量结果。没有用户指定的数据文件就跳过历史检索，不扫描其他项目。

## 4. 交付、反馈与归档

普通搜索只交付本轮要求的字段。需要详细报告或归档时读取 [references/delivery-format.md](references/delivery-format.md)。

用户纠正候选方向时，把纠正用于本轮扩搜。用户明确要求沉淀时才读取 [references/learning-loop.md](references/learning-loop.md)，将稳定判断覆盖写入外部 Profile，将案例和反例追加到外部语料库；Skill 本体保持不变。

## 完成标准

- 单条核验：有结论、详情证据和未核实项。
- 漏检复查：有漏检原因和补搜结果。
- 主题搜索：用户完成方向校准，最终候选满足 Brief。
- 系统建库：Brief 范围内新增、重复、排除和缺口均已报告。
- 归档：最终保留项再次去重，必填字段完整。

# 通用搜索与复核协议

## 搜索矩阵

从 Brief 生成四类词：

- **主题词**：赛道、产品、方法和内容类型。
- **用户词**：观众会用来称呼自己的身份、阶段和处境。
- **场景词**：具体任务、障碍、代价、冲突和期望结果。
- **平台词/Tag**：候选详情中出现的行业词、产品词、栏目词和真实 Tag。

先用“用户词 × 场景词”寻找目标用户会点击的表达，再补主题词和 Tag。每条高质量候选都提取标题结构、真实 Tag、用户自称和评论区问题，作为下一轮扩搜入口。

## 三层漏斗

### 发现层

- 在小红书站内检查与 Brief 有关的综合、图文和视频结果。
- 只记录标题、链接、卡片日期、主要互动指标和一句人群判断。
- 主题搜索获得 5–8 条高潜候选后暂停，先让用户校准。

### 复核层

只打开方向正确且可能达到门槛的候选，核验标题、作者、发布日期、筛选所需互动数据、全部可见 Tag、图文/视频和播放器时长。

页面显示编辑日期或日期存疑时，寻找最早可见评论等证据。证据不足时标记未核实，不进入确认清单。

### 入库层

只对最终保留、且用户要求详细交付或归档的内容提取封面、正文图片、完整互动数据、高赞评论、稳定分享链接等昂贵字段。

## 漏检复查

1. 核验用户给出的笔记是否符合 Brief。
2. 定位漏在标题词、Tag、用户词、场景词、日期、排序还是去重。
3. 沿标题结构、真实 Tag、目标用户和具体场景分别补搜。
4. 报告新增候选与应加入本轮搜索矩阵的新入口。

## 停止条件

- 单条核验不扩搜。
- 漏检复查完成四个入口各一轮后停止。
- 主题搜索和系统建库在覆盖 Brief 指定分支后，连续两个扩展分支没有新增合格候选时停止。

结论只覆盖实际执行的搜索矩阵和可见结果范围，不宣称穷尽整个平台。
